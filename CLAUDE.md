# Kaggle workspace rules

These rules apply to every Kaggle competition worked on in this folder (`e:\Kaggle`).

## Repo and folders
- `e:\Kaggle` is the git repo `https://github.com/vinayassrao/Kaggle_Submission.git` (branch `main`).
- One folder per competition, named **exactly as the competition title on Kaggle** (e.g. `Titanic - Machine Learning from Disaster`, `Predicting Credit Card Fraud`).
- Competition data goes in `<competition>/data/`. It is gitignored. **Never commit competition data** (Kaggle rules).
- The root `README.md` is a scoreboard: one row per competition with its best public score and a link to its folder. Update it whenever the user reports a new score.
- Each competition folder has its own `README.md`: task, metric, setup, every iteration with CV score and public score.

## Modelling workflow
1. Read the competition's evaluation metric and submission format first (ask the user to paste the Evaluation text if the page can't be read).
2. Start with a simple **baseline**, then improve in **numbered iterations** (`v1_...py`, `v2_...py`, ...). Keep every iteration's script and its submission file; never overwrite earlier ones.
3. Score every iteration with **K-fold cross-validation using the competition's metric**, and record it (`results.csv`). An iteration only counts as better if the gain is larger than the CV noise.
4. Avoid leakage: anything computed from the target must be built inside each CV fold.
5. Write submissions to `<competition>/submissions/` in the exact format of `sample_submission.csv`.
6. Give the user a **short** submission description for each file (one line, e.g. "LightGBM + engineered features (CV AUC 0.912)").
7. **Run heavy jobs one at a time** (training, CV, EBM, stacking, diagnostics). Never start a second one while another runs; the machine has 16.8 GB RAM and parallel jobs caused an out-of-memory crash. Chain them sequentially (`a && b && c`) or wait for completion.

## Beginner guide (required after every completed model)
After modelling for a competition is complete (and again whenever new iterations are added), create or update `<competition>/guide/<Name>_Beginner_Guide.md`:
- Written for a complete beginner who should be able to redo the project alone.
- Every key idea gets an **"Explain like I'm 5"** blockquote before the technical explanation.
- Covers **every iteration of the model** and explains **why each one is better than its predecessor** (with the CV score change).
- Has a detailed **"Terms and techniques" section**: every terminology and technique used in the project (metrics, models, encodings, validation, tuning, imbalance handling, ensembling...) explained in depth (how it works, why it is used, the key settings) AND with an "Explain like I'm 5" version for each one.
- If the competition's data comes from a public original dataset, use the dataset's description: its suggested analyses become extra iterations/analysis sections, and try adding the original data to training as an iteration.
- Includes diagrams (PNG, generated by `guide/make_diagrams.py` with matplotlib, light theme, consistent palette) and real numbers from the actual runs.
- Includes setup, step-by-step runnable code, common mistakes, next steps and a glossary.
- Kept as Markdown; convert to PDF only when the user asks.

## Git
- Commit and push to `main` after each competition's work (and after score updates).
- After a competition is pushed, the user may ask to delete it locally. Do it with sparse-checkout so git does not record a deletion:
  - add `!/<competition folder>/` to `.git/info/sparse-checkout` (write the file directly; Git Bash mangles paths passed to `git sparse-checkout set`), then `git sparse-checkout reapply`.
  - First confirm everything except `data/` is pushed. `git sparse-checkout disable` brings folders back.

## Environment notes
- Windows, Python 3.14, Git Bash + PowerShell. No Kaggle API token is set up: the user downloads data manually into `data/`.
- **GPU: NVIDIA RTX 3050 Laptop, 6 GB.** Use it where possible: XGBoost `device="cuda"` ✅, CatBoost `task_type="GPU"` ✅. LightGBM pip build is CPU-only (no `device_type="gpu"`). scikit-learn / interpret (EBM) are CPU-only. PyTorch is not installed; install the CUDA build for neural nets.
- **Whenever a needed dataset file is missing, give the user the direct download link** (competition Data tab, e.g. `https://www.kaggle.com/competitions/<slug>/data`, or the original dataset's Kaggle page) together with the exact folder to put it in. Never just say "re-download it".
- Kaggle pages render client-side, so web fetches only return the title. Ask the user for the Overview/Evaluation text.
